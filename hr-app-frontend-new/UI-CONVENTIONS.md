# UI conventions (shadcn/ui + Tailwind v4)

The frontend is built on [shadcn/ui](https://ui.shadcn.com) (Radix primitives, `vega`
style) with Tailwind CSS v4. React Bootstrap and Bootstrap CSS are gone; don't bring
them back. **Reference implementation:** `src/pages/DepartmentsPage.jsx` +
`src/components/DepartmentModal.jsx`. When in doubt, copy what they do.

## Where things live

| Path | What |
|---|---|
| `src/components/ui/*` | shadcn primitives, generated by the CLI. Don't hand-edit; re-add with `npx shadcn@latest add <name>`. |
| `src/components/app/*` | App-level building blocks shared by every page (below). |
| `src/index.css` | Tailwind entry, theme tokens (light + `.dark`). The only stylesheet. |
| `src/lib/utils.js` | `cn()` for merging class names. |

Import with the `@/` alias: `import { Button } from '@/components/ui/button'`.

## App building blocks (`src/components/app`)

| Component | Use for |
|---|---|
| `ItemCard` + `MetaList` | Every card a `DataPage` renders: icon tile, title, subtitle, badge, body, actions. |
| `StatusBadge` | Coloured pills. `tone`: primary, success, warning, danger, info, violet, muted, or `status="Approved"`. Other props (`title`, …) pass through. |
| `IconTile` | Tinted icon square. `tone`: indigo, violet, sky, green, amber, red, muted. |
| `PageHeader`, `SectionTitle` | Title block and section headings on pages that don't use `DataPage`. |
| `StatCard` | Headline numbers (dashboards, analytics). With `to`, the whole card links there. |
| `ConfirmDialog` | Any "are you sure?" step. Replaces `window.confirm` and Bootstrap confirm modals. |
| `EmptyState` | "Nothing here yet" blocks. |
| `BrandMark` | The product logo tile (shell, landing, login). |
| `DocPreview` | Rendered document HTML: always white paper, with `prose` typography, in both themes. |

## Bootstrap → shadcn

| Was | Now |
|---|---|
| `Modal show onHide` | `Dialog open={show} onOpenChange={(o) => { if (!o) onHide(); }}` → `DialogContent` (`className="sm:max-w-lg"`, `sm:max-w-2xl` for wide) → `DialogHeader`/`DialogTitle`/`DialogDescription`, body, `DialogFooter`. Put a `<form onSubmit>` *inside* `DialogContent` around header, body and footer, and make the primary button `type="submit"`. |
| `Card`, `Card.Body` | `Card`/`CardHeader`/`CardTitle`/`CardDescription`/`CardContent`/`CardFooter`, or `ItemCard` for list items. |
| `Button variant="primary"` / `"secondary"` / `"outline-*"` / `"danger"` / `"link"` | `Button` (default) / `variant="outline"` / `"outline"` or `"ghost"` / `"destructive"` / `"link"`. Icon-only: `size="icon-sm"` + `aria-label`. |
| `Form.Group` + `Form.Label` + `Form.Control` | `Field` + `FieldLabel htmlFor` + `Input id` (`Textarea` for `as="textarea"`). Group fields in `FieldGroup`; hints in `FieldDescription`; errors in `FieldError`. Two columns: `<div className="grid gap-4 sm:grid-cols-2">`. |
| `Form.Select` | **`NativeSelect` + `NativeSelectOption`** (always native: keyboard-friendly and tests can `fireEvent.change` it). Pass `className="w-full"` in forms. |
| `Form.Check` (checkbox / switch / radio) | `Checkbox` / `Switch` (`onCheckedChange`) / `RadioGroup` + `RadioGroupItem` (`onValueChange`), each with a `Label htmlFor`. |
| `Alert variant="danger"` | `<Alert variant="destructive"><AlertCircle /><AlertDescription>…` |
| `Alert variant="info"` / `"warning"` / `"success"` | `<Alert>` with `className="border-sky-500/30 bg-sky-500/5"`, `"border-warning/40 bg-warning/10"` or `"border-success/40 bg-success/10"`, plus the matching lucide icon. |
| `Badge`, `.status-chip.is-*` | `StatusBadge`: `is-success`/`is-approved` → `success`, `is-pending` → `warning`, `is-rejected`/`is-danger` → `danger`, `is-info` → `info`, `is-primary` → `primary`. |
| `.item-card-icon.tone-*` | `IconTile` with the same tone name. |
| `Table` | `Table`/`TableHeader`/`TableRow`/`TableHead`/`TableBody`/`TableCell`. |
| `Tabs`/`Tab` | `Tabs`/`TabsList`/`TabsTrigger`/`TabsContent`. |
| `Dropdown` | `DropdownMenu`/`DropdownMenuTrigger asChild`/`DropdownMenuContent`/`DropdownMenuItem`. |
| `Spinner`, `spinner-border` | `Spinner` (in buttons: `{busy && <Spinner />}`). |
| `ProgressBar now` | `Progress value`. |
| `.skeleton` | `Skeleton className="h-…"`. |
| `ListGroup` | A `Card` with `divide-y` rows, or `Table` when the data is tabular. |
| `Row`/`Col` | `grid gap-4 md:grid-cols-2 xl:grid-cols-3` (or `flex`). |
| `title="…"` tooltips on icon buttons | Keep `aria-label`; add `Tooltip` only where the meaning isn't obvious. |
| `window.confirm(...)` | `ConfirmDialog`. |

### Utility classes

Bootstrap spacing steps (1=.25rem, 2=.5rem, **3=1rem**, **4=1.5rem**, **5=3rem**) are not
Tailwind's. Bootstrap `mb-3` → Tailwind `mb-4`, `mb-4` → `mb-6`, `mb-5` → `mb-12`.

`d-flex` → `flex` · `align-items-center` → `items-center` · `justify-content-between` →
`justify-between` · `flex-grow-1` → `flex-1` · `text-muted` → `text-muted-foreground` ·
`small` → `text-sm` (or `text-xs`) · `fw-semibold`/`fw-bold` → `font-semibold`/`font-bold` ·
`w-100` → `w-full` · `text-truncate` → `truncate` · `visually-hidden` → `sr-only` ·
`text-danger` → `text-destructive` · `text-success` → `text-success` · `text-end` → `text-right`.

## Colour and dark mode

- Use the **tokens**: `bg-background`, `bg-card`, `bg-muted`, `text-foreground`,
  `text-muted-foreground`, `border`, `text-primary`, `bg-primary/10`, `text-destructive`,
  `bg-success/15 text-success`, `bg-warning/15 text-warning`. They switch with the theme.
- Never hard-code hex colours. A Tailwind palette colour (sky, violet) needs a `dark:`
  partner, as `tones.js` shows. Prefer the tones in `tones.js`.
- Dark mode is the `.dark` class on `<html>` (`services/themeService.js`).
- Rendered documents stay white in both themes: use `DocPreview`.

## Layout

- Pages render inside the shell's `max-w-7xl` container. Don't add page-level padding.
- Page title: `DataPage` renders its own (`headingLevel={2}` when it is a section of a larger page). Otherwise use `PageHeader` (an `h1`). The top bar
  holds the shell's `h1`-sized page name. Keep a single `h1` per page body: `PageHeader`'s.
- Stack sections with `space-y-6`. Card grids: `grid gap-4 md:grid-cols-2 xl:grid-cols-3`.
- Everything must work at 375px wide: wrap toolbars with `flex-wrap`, and let tables
  scroll (`Table` already wraps itself in an overflow container).

## Rules

- **No CSS files** besides `index.css`, no `style={{}}` except genuinely dynamic values
  (a bar's height, a computed colour).
- **Keep component contracts.** Exported names and props stay the same, including the
  modal contract `show` / `onHide` / `onSave` (plus `onGenerate`, `editingTemplate`
  where they exist), because `DataPage` and other pages call them.
- **Keep behaviour.** This is a visual change. Don't alter API calls, validation or state
  logic. If you find a bug, note it rather than fixing it in passing.
- **Tests:** existing tests must keep passing with their assertions intact. If a test
  located something through a Bootstrap class (`.btn-outline-danger`, `.list-group-item`),
  switch it to role / label / text queries (`getByRole('button', { name: 'Delete X' })`).
  Never delete a test or loosen what it checks.
- Accessibility: every control has a visible label or an `aria-label`; icon-only buttons
  always have an `aria-label`; keep existing `aria-*` and `role` attributes.
